# AIIairs: 전국 소극장·소공연 일정

대학로 2인극, 홍대 인디 라이브, 하우스 콘서트처럼 **작은 무대**만 모아 보여주는 사이트예요.
KOPIS 공연 중 **공연장 좌석이 300석 이하**인 것만 싣고(대극장·아레나는 제외), 장르별로 나눠요.

정적 사이트 하나(`index.html`)와, 매일 일정을 모아 `data/fairs.json`을 만드는 수집기로 이루어져 있어요.
이 폴더(`aiiairs/`)를 그대로 웹 서버에 올리면 돼요.

```
aiiairs/
├─ index.html             페이지. data/fairs.json 을 읽고, 없으면 안에 든 예시 일정을 보여줌
├─ data/
│  ├─ fairs.json          수집 결과 (자동 생성, 직접 고치지 않음)
│  └─ manual.csv          API에 없는 소공연을 직접 넣는 곳
├─ img/                   포스터가 없을 때 쓰는 그림 (Fluent Emoji, MIT)
└─ scripts/
   ├─ collect.py          수집기 (Python 표준 라이브러리만 사용)
   ├─ test_collect.py     수집기 테스트
   └─ fixtures/           테스트용 예시 응답 (가상 데이터)
```

## 일정이 들어오는 길

| 출처 | 무엇 | 필요한 것 |
|---|---|---|
| `data/manual.csv` | 카페 공연, 골목 버스킹처럼 API에 없는 소공연 | 없음 (파일만 채우면 됨) |
| [KOPIS 공연예술통합전산망](https://kopis.or.kr/por/cs/openapi/openApiInfo.do?menuId=MNU_00074) | 연극·뮤지컬·콘서트 등 공연 | `KOPIS_API_KEY` |
| [한국문화정보원 한눈에보는문화정보](https://www.data.go.kr/data/15138937/openapi.do) | 공연 (전시·축제는 제외) | `DATA_GO_KR_KEY` (공공데이터포털 **디코딩** 키) |

같은 행사가 여러 출처에 있으면 한 번만 남기며, 위 표의 순서대로 먼저 온 출처를 우선해요.
키가 없는 출처는 건너뛰고, 모든 출처에서 한 건도 못 얻으면 기존 `fairs.json`을 그대로 둬요.

## 처음 설정

1. **API 키 신청**
   - KOPIS: kopis.or.kr → 고객지원 → Open API → 인증키 신청
   - 한국문화정보원: data.go.kr → '한국문화정보원_한눈에보는문화정보조회서비스' → 활용신청
2. **GitHub에 키 등록**: 저장소 Settings → Secrets and variables → Actions → New repository secret
   - `KOPIS_API_KEY`, `DATA_GO_KR_KEY`
3. **자동 실행**: `.github/workflows/aiiairs-collect.yml`이 매일 05:43(한국 시간)에 돌아요.
   Actions 탭에서 'AIIairs 일정 수집' → Run workflow 로 바로 돌려볼 수도 있어요.
   GitHub Actions의 예약 실행은 **기본 브랜치**에 있는 워크플로만 동작해요.
4. **예시 일정 끄기**: `data/fairs.json`이 생기면 페이지가 자동으로 실제 일정을 보여주고,
   상단의 '예시 일정' 표시 대신 갱신 시각과 출처를 보여줘요.

## 사이트 공개 (GitHub Pages)

`.github/workflows/aiiairs-pages.yml`이 `aiiairs/` 폴더를 GitHub Pages로 올려요. 주소는 `https://45516645sud-stack.github.io/-/`예요.

- **처음 한 번만**: 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 바꾸기
- 그다음부터는 자동이에요. 사이트 파일을 고쳐 기본 브랜치에 올리거나, 매일 새벽 일정 수집이 끝나면 다시 올라가요.
  (수집 로봇이 만든 커밋은 다른 자동 작업을 깨우지 않아서, 수집 워크플로가 끝나는 것을 신호로 받아요.)
- 올라가는 것: `index.html`, `privacy.html`(개인정보 처리방침), `og.png`(링크 공유 미리보기 그림), `robots.txt`, `sitemap.xml`, `img/`, `data/fairs.json`, 그리고 올릴 때 받은 `posters/`. 수집 스크립트와 `manual.csv`는 올리지 않아요.

## 전국 공연을 전부 모으기

KOPIS에서 오늘부터 180일 동안의 공연을 **한도 없이 전부** 가져온 뒤, 300석 이하 공연장만 남겨요.

- 공연마다 상세(요금·공연장·예매처)를 한 번씩 물어봐야 해서, **처음 한 번은 오래 걸려요** (최대 2시간으로 잡아 둠).
- 한 번 물어본 상세는 7일, 공연장 좌석 수는 60일 동안 기억해 두고 다시 묻지 않아요. 그래서 다음 날부터는 새 공연만 물어봐요.
  기억은 저장소가 아니라 GitHub Actions 캐시(`aiiairs/.cache/`)에 둬요.
- 한 번에 새로 물어보는 상세는 6,000건까지예요(`--kopis-detail`). 넘치는 공연은 큰 공연장인지 아직 모르니 싣지 않고, 다음 날 마저 물어봐서 실어요.
- KOPIS에 없는 공연(카페 공연, 버스킹, DM으로만 표를 파는 공연)은 `data/manual.csv`로 넣어요.

## 공식 포스터

포스터는 **저장소에 넣지 않아요.** 매일 바뀌는 사진을 저장소에 쌓으면 지운 사진까지 기록에 남아 저장소가 계속 커지기 때문이에요.
대신 사이트를 올릴 때(`aiiairs-pages.yml`) KOPIS 공식 포스터를 내려받아 가로 360px WebP로 줄여 함께 올려요.
받아 둔 포스터는 GitHub Actions 캐시에 두고 새 공연 것만 받아요.
포스터를 못 받은 공연은 KOPIS 포스터 주소를 바로 쓰고, 그것도 안 되면 장르 그림으로 만든 포스터가 나와요.

3. 그 밖에는 넣어요.
상세 화면에는 'OO석 규모'로 표시돼요.

## 결과가 없을 때 (막다른 길 대신 대안)

찾는 조건에 맞는 행사가 없으면 페이지가 스스로 이렇게 해요.

1. **왜 없는지 + 조건 하나만 풀면 뭐가 있는지**: 예산 → 날짜 → 무료 여부 → 지역 → 분야 순으로 하나씩만 풀어 보고, 실제로 행사가 나오는 것만 보여줘요.
   예) "2만 원 이하는 없지만 3만 원까지 넓히면 2개 있어요", "그 날짜엔 없지만 다음 주 토요일(10.10)엔 1개 있어요"
   누르면 '원래 조건엔 없어서 넓혀 찾은 결과'라고 표시하고, '원래 조건으로' 되돌릴 수 있어요.
2. **알림 받기**: 조건을 이 브라우저에 저장해 두었다가, 다시 들어왔을 때 새로 생긴 행사가 있으면 맨 위에 먼저 알려줘요.
   (서버 없이 동작하는 방식이라 이메일·문자 알림은 아니에요. 필요하면 나중에 서버를 붙여 확장할 수 있어요.)
3. **기록**: 결과가 없던 검색과 알림 신청을 운영자 구글 시트에 남겨요. 사람들이 찾는데 없는 행사를 보여주는 자료라서,
   다음에 어떤 공연을 추가할지 정하는 데 써요. 검색 조건만 보내고 개인정보는 보내지 않아요.

### 기록 켜기 (구글 시트, 무료)

1. 구글 시트를 새로 만들고 → 확장 프로그램 → Apps Script
2. `scripts/miss-log.gs` 내용을 붙여 넣고 저장
3. 배포 → 새 배포 → 유형 **웹 앱**, 실행 계정 **나**, 액세스 **모든 사용자** → 배포
4. 나온 주소(`https://script.google.com/macros/s/…/exec`)를 `index.html`의
   `<meta name="aiiairs-log-endpoint" content="">` 따옴표 안에 넣기

켜면 시트에 '결과 없음', '알림 신청', '의견' 탭이 생기고 한 줄씩 쌓여요. 페이지 아래에도 기록한다는 안내가 자동으로 나와요.
주소를 비워 두면 아무것도 보내지 않아요.

## 사용 의견 묻기

사이트에 **들어올 때마다**, 그 방문에서 5분쯤 본 사람에게 오른쪽 아래(핸드폰은 화면 아래)에 **딱 한 번** 물어봐요. 다음에 다시 들어오면 또 5분 뒤에 한 번 물어봐요.

- "사용은 어떠신가요?" → **1 별로예요** / **2 좋아요**
- 1을 누르면 "왜 별로이신가요? 개선점을 적어 주시면 감사합니다."
- 2를 누르면 "왜 좋으신가요? 좋았던 점을 적어 주시면 감사합니다."
- 이유를 다 쓰기 귀찮은 사람을 위해 자주 나올 이유(예: '찾는 공연이 없어요', '포스터로 고르기 쉬워서')를 눌러 고를 수도 있어요.
- 답은 구글 시트 '의견' 탭에 쌓여요 (시각, 평가, 고른 이유, 의견, 사용 시간, 모바일/PC). 글을 안 쓰고 건너뛰어도 1·2 평가는 남아요.
- 다른 탭에 가 있던 시간은 세지 않고, 같은 방문에서는 한 번만 물어봐요. 공연 상세를 보는 중에는 끼어들지 않아요.
- 위 **기록 켜기**를 해야 물어봐요. 받을 곳이 없는데 묻는 건 방문자에게 실례라서요.
- 주소 끝에 `?feedback=1`을 붙이면 5분을 기다리지 않고 바로 띄워 볼 수 있어요.
- **운영자 모드**: 주소 끝에 `?owner=1`을 붙여 한 번 들어오면, 그 브라우저에서는 들어올 때마다 바로 떠요 (`?owner=0`으로 끔). 이때 창에 '운영자 시험'이라고 나와요.

## 방문 통계 (구글 시트 '방문' · '많이 본 공연' 탭)

의견과 같은 구글 시트에 **숫자만** 쌓아요. 누가 했는지(이름·IP 등)는 보내지 않아요.

- **방문** 탭: 하루 한 줄. 방문(탭마다 한 번) · 모바일 · PC · 공연 열기 · 검색 · 예매 클릭 · KOPIS 정보 · 지도 · 링크 복사 · 캘린더
- **많이 본 공연** 탭: 공연 이름별로 열어 본 횟수와 마지막으로 본 날. 시트에서 '데이터 → 정렬'로 많이 본 순으로 볼 수 있어요.
- 운영자 모드(`?owner=1`)로 본 것은 세지 않아요.
- 방문은 들어오자마자 보내고, 나머지 숫자는 모아 두었다가 화면을 떠날 때(다른 탭·닫기) 한 번에 보내요. 구글 Apps Script 하루 사용량을 아끼려고요.
- 숫자 한 번에 최대 500까지만 더해요 (누가 장난으로 큰 숫자를 보내도 통계가 크게 망가지지 않게).

`scripts/miss-log.gs`를 바꾼 뒤에는 Apps Script에 붙여 넣고 **배포 → 배포 관리 → ✏️ 편집 → 버전: 새 버전 → 배포**를 해야 반영돼요 (주소는 그대로).

## 취향 검색 점검 (222개 문장)

검색을 고치다가 다른 검색을 망가뜨리지 않도록, 문장 222개의 정답을 저장해 두고 진짜 브라우저로 다시 검색해 비교해요.

| 파일 | 내용 |
|---|---|
| `scripts/search/cases.txt` | 점검할 문장 (한 줄에 하나) |
| `scripts/search/fixture.json` | 고정 공연 데이터 (2026-10-11 실제 일정 + 시험용 7개). 날짜는 2026-10-12로 고정 |
| `scripts/search/snapshot.json` | 정답: 문장마다 '이렇게 읽었어요' 내용, 안내 문구, 건수, 위 5개 |
| `scripts/search/check.mjs` | 점검 프로그램 |

```bash
node aiiairs/scripts/search/check.mjs            # 점검 (다르면 어디가 달라졌는지 보여주고 실패)
node aiiairs/scripts/search/check.mjs --update   # 일부러 바꾼 뒤 지금 결과를 새 정답으로 저장
```

GitHub에서는 `index.html`이나 점검 파일이 바뀌면 'AIIairs 검색 점검'이 자동으로 돌아요. 새로 고친 검색어는 `cases.txt`에 더하고 `--update`로 정답을 만들어 함께 올려요.

- **관람 나이**: '만 7세 이상' 등을 숫자로 바꿔 두고, "5살 아이"처럼 나이를 적으면 그 나이가 볼 수 없는 공연은 빼요
- **자동 꼬리표**: 공연 이름·소개·장르에 '코미디', '추리', '2인극', '낭독', '재즈' 같은 말이 있으면 웃음·공포·2인극·낭독·재즈 등의 꼬리표
- **출연진**: 배우 이름으로도 찾아요
- **사전에 없는 말**은 공연 이름·공연장·출연진에서 찾아요 (`우리들의 계절`, `씨어터조이`). 단, 사전에 있는 말·날짜·가격 말과 너무 흔한 말(공연의 4% 넘게 들어 있는 말)은 이름으로 보지 않아요. 찾지 못한 말은 "아직 알아듣지 못하는 말"이라고 알려줘요.
